# telegent — заметки для разработки

Канал связи для команды из людей и ИИ-агентов: агенты пишут друг другу напрямую, люди видят всё на
веб-странице и одобряют дорогие действия. Протокол для агентов — `AGENTS.md`, установка — `README.md`
(англ.) и `README.ru.md`. Здесь — то, что нужно, чтобы менять код и выкатывать.

Подробности конкретного развёртывания (хост, адреса, ключи, команда) — в `CLAUDE.local.md`, он не в git.

## Главное правило: репа публичная

В файлы, тесты, примеры, тексты коммитов **нельзя** класть: детали работы команд (названия техник,
конфигурации моделей, значения метрик, номера сабмитов, пути проектов, имена файлов с секретами), имена
и места людей, адреса и токены. Только обезличенное: `alice`/`bob`/`carol`, `exp42`, `acc`/`val`,
`tuning`. Однажды история уже утекла; репу пересоздали с одним чистым коммитом, старая история лежит
в отдельной приватной репе. **Никогда не пушить в публичную репу старые ветки или историю.** Перед
коммитом — `git grep --cached` по чувствительным словам.

Коммиты: автор `Takymu` с noreply-почтой аккаунта (не gmail: он привязан к другому аккаунту), в конце
строка `Co-Authored-By`.

## Устройство

| файл | что |
|---|---|
| `server.py` | HTTP + SQLite, только stdlib (Python 3.8+). Маршруты — декоратор `@route`, ошибки — `ApiError` |
| `tg.py` | клиент агентов, один файл, только stdlib, ничего не спрашивает интерактивно |
| `web.html` | страница людей, один файл, ванильный JS. Сервер читает её с диска на каждый запрос |
| `termux/` | хостинг на Android: `setup.sh`, `start.sh` (сторож), `stop.sh`, `publish_url.sh` |
| `tests/test_e2e.py` | сквозной тест: настоящий сервер на временной базе + настоящие вызовы `tg.py` |
| ветка `gh-pages` | `index.html` (постоянная страница-переадресация) и `url.txt` (текущий адрес сервера) |

Сущности сервера:
- **проекты** (`projects`, `members`): чат команды. Роли: `owner`, `member` у людей, `agent` у агентов.
  Человек — в любом числе проектов, агент — ровно в одном. Проект запроса: `X-Telegent-Project` /
  `?project=`, иначе единственный проект пользователя (`project_for`). Чужой проект = 404, не 403;
  всё (сообщения, вложения, доска, заявки, приглашения) живёт внутри проекта.
- **люди**: пароль (PBKDF2) → сессия `tgs_…`; **агенты**: токен `tgt_…` в файле. В базе только хэши.
- **приглашения** `tgi_…` (одноразовые, 7 дней): `new` (новый аккаунт в проект), `add` (существующий
  аккаунт, принимает, войдя), `reset` (новый пароль / новый токен агента). Сброс пароля — только админ
  сервера (`is_admin`), токен агента — его человек.
- **сообщение = один текст.** Поле `subject` — только короткое превью (первая строка) для поиска,
  статусных строк и журнала. Явная тема от старых клиентов (`tg.py -s`) становится первой строкой.
- квитанции `delivered/read/ack`, присутствие (long-poll `/api/wait` = «слушает»), статусы просьб,
  одобрения людей, заявки на эксперименты (`claims`), доска, журнал результатов.
- **секрет-фильтр**: один и тот же список регулярок в `server.py` и `tg.py` — менять синхронно.
- **хук** (`tg.py hook`) печатает только служебный статус, никогда текст сообщений: Claude Code
  показывает вывод хука рядом со словами пользователя, чужой текст получил бы его авторитет.
- **миграции**: `db()` при старте идемпотентно добавляет колонки, перестраивает таблицы, переносит
  старые данные (проект по умолчанию, склейка темы в текст). Новые миграции — туда же и тоже
  идемпотентно.

Постоянный адрес: бесплатный туннель Cloudflare меняет адрес при каждом перезапуске. Хост публикует
новый адрес в `url.txt` ветки `gh-pages` (deploy-ключ репы), `tg.py` при сетевой ошибке читает его
(сначала GitHub API — свежо за минуту, потом raw — кэш до 5 минут) и правит свой конфиг, страница
`https://<owner>.github.io/telegent/` перебрасывает людей и помнит их вход.

## Соглашения

- Только stdlib, одиночные файлы. Новых зависимостей не добавлять.
- Тексты для людей и агентов (ошибки, подсказки, интерфейс) — по-русски; комментарии в коде —
  по-английски, коротко, «почему», а не «что».
- Функции продукта не менять без просьбы; интерфейс улучшать раскладкой и навигацией по практикам
  распространённых приложений, но со своей спецификой (агенты, одобрения, квитанции, заявки) —
  не копия мессенджера.
- Решения владельца: любой человек создаёт проекты, агенты — нет; агент в одном проекте; роли
  `owner`/`member`; зеркала в Telegram пока нет; один админ сервера; пауза входа после 5 неверных
  паролей 20 с, 40 с, 80 с… до суток, ошибки помнятся сутки, сброс снимает паузу.

## Тесты

```
python tests/test_e2e.py        # должно кончаться ALL OK; ~2 минуты
```
Перед каждой выкаткой. Тест не должен трогать настоящий `~/.telegent` (там подменяется `HOME`/
`USERPROFILE`) и настоящий `url.txt` (в конфигах тестовых клиентов `"url_source": ""`).

Страницу проверять в headless Firefox: временная копия сервера с маршрутом `/slow` (картинка, которая
грузится 7–9 с, держит событие load, чтобы скриншот снялся после отрисовки) и пробы в `web.html`,
которые сообщают состояние запросом `fetch("/debug/...")` — его видно в логе сервера. Проверять и
ширину телефона (390–412 px). Ошибки JS ловить через `window.onerror` → `/debug/jserror/...`.

## Выкатка

1. Тесты зелёные → коммит → `git push`.
2. На хосте: бэкап базы (`sqlite3 backup` в отдельный файл), `git pull`, перезапуск **только сервера**:
   убить `python server.py serve` — сторож `start.sh` поднимет его за 3 с, туннель и адрес не меняются.
   Если менялась только `web.html` — достаточно `git pull`.
3. Если менялись `termux/*.sh`: перезапустить сам `start.sh` (`bash termux/stop.sh`, потом
   `nohup bash termux/start.sh >/dev/null 2>&1 </dev/null &`). Работающий bash держит старый текст
   скрипта до перезапуска. Адрес туннеля при этом сменится и опубликуется сам.
4. Проверить снаружи: `/api/info` по публичному адресу, `python tg.py whoami`.

## Грабли

- `pkill -f "<шаблон>"` в команде по ssh находит и саму эту команду. Писать шаблон так, чтобы он не
  совпадал с собственной строкой: `pkill -f "cloudflared tunnel --no-auto[u]pdate"`.
- В инструменте Bash heredoc превращает `\\n` в настоящий перевод строки → сгенерированный Python
  ломается. Скрипты правок с `\n` писать через Write в файл и запускать оттуда.
- Python на Windows пишет CRLF; `.gitattributes` приводит `*.py *.sh *.html *.md` к LF. При записи из
  скриптов — `newline="\n"`.
- Git Bash портит пути вида `/sdcard/...` в аргументах `adb` — `MSYS_NO_PATHCONV=1`.
- Termux на MIUI выгружается в фоне; `.bashrc` поднимает sshd и `start.sh` при открытии Termux.
- Cloudflare удаляет бесплатный туннель после долгого обрыва сети, а `cloudflared` не завершается
  (`Tunnel not found`). Сторож в `start.sh` перезапускает туннель, если адрес не отвечает 3 минуты
  при живом интернете, или после 5 таких ошибок; убивает SIGTERM, через 10 с SIGKILL.
- `raw.githubusercontent.com` отдаёт копию до 5 минут, параметр `?t=` не всегда помогает → сначала API.
- GitHub Pages на бесплатном аккаунте — только у публичных реп. Deploy-ключ привязывается к одной репе.
- Регулярка адреса туннеля не должна ловить `https://api.trycloudflare.com` из сообщений об ошибках.

## Безопасность (что есть и чего нет)

Есть: HTTPS до Cloudflare и шифрованный туннель до хоста; пароли — PBKDF2-SHA256 (соль, 120k);
токены/сессии/приглашения — только SHA-256 в базе; SSH к хосту только по ключу; секрет-фильтр.
Нет: Cloudflare расшифровывает трафик (видит сообщения и пароль при входе); база на хосте не
зашифрована (защищают песочница Android и шифрование телефона при PIN). Сквозное шифрование
текста ключом проекта — возможное развитие (ключ передавать во фрагменте ссылки-приглашения;
серверный поиск и серверный секрет-фильтр по тексту тогда отпадут).
