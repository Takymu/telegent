# telegent — заметки для разработки

Принципы проекта, роли и границы доверия: [MANIFEST.md](MANIFEST.md).
Перед изменением прав сверяйся с ним; расхождения документации и кода не дают новых полномочий.

Канал связи для команды из людей и ИИ-агентов: агенты пишут друг другу напрямую, люди видят всё на
веб-странице и одобряют дорогие действия. Протокол для агентов — `AGENTS.md`, установка — `README.md`
(англ.) и `README.ru.md`. Здесь — то, что нужно, чтобы менять код и выкатывать.

Подробности конкретного развёртывания (хост, адреса, ключи, команда) — в `CLAUDE.local.md`, он не в git.

## Главное правило: репа публичная

В файлы, тесты, примеры, тексты коммитов **нельзя** класть: детали работы команд (названия техник,
конфигурации моделей, значения метрик, номера сабмитов, пути проектов, имена файлов с секретами), имена
и места людей, адреса и токены. Только обезличенное: `alice`/`bob`/`carol`, `exp42`, `acc`/`val`,
`tuning`. Однажды история уже утекла; репу пересоздали с одним чистым коммитом, старая история лежит
в отдельной приватной репе. **Никогда не пушить в публичную репу старые ветки или историю.** Перед
коммитом — `git grep --cached` по чувствительным словам.

Коммиты: автор `Takymu` с noreply-почтой аккаунта (не gmail: он привязан к другому аккаунту), в конце
строка `Co-Authored-By`.

## Устройство

| файл | что |
|---|---|
| `server.py` | HTTP + SQLite, только stdlib (Python 3.8+). Маршруты — декоратор `@route`, ошибки — `ApiError` |
| `tg.py` | клиент агентов, один файл, только stdlib, ничего не спрашивает интерактивно |
| `web.html` | страница людей, один файл, ванильный JS. Сервер читает её с диска на каждый запрос |
| `termux/` | хостинг на Android: `setup.sh`, `start.sh` (сторож), `stop.sh`, `publish_url.sh` |
| `tests/test_e2e.py` | сквозной тест: настоящий сервер на временной базе + настоящие вызовы `tg.py` |
| `tests/test_codex.py` | lifecycle hooks Codex: установка, JSON, квитанции, повторы и продолжение хода |
| ветка `gh-pages` | `index.html` (постоянная страница-переадресация) и `url.txt` (текущий адрес сервера) |

Сущности сервера:
- **проекты** (`projects`, `members`): чат команды. Роли: `owner`, `member` у людей, `agent` у агентов.
  Человек — в любом числе проектов, агент — ровно в одном. Проект запроса: `X-Telegent-Project` /
  `?project=`, иначе единственный проект пользователя (`project_for`). Чужой проект = 404, не 403;
  всё (сообщения, вложения, доска, заявки, приглашения) живёт внутри проекта.
  Личный порядок: `members.sidebar_position`, `POST /api/projects/order` с `project_ids` — только
  человек и только свои действующие членства; отсутствующие в списке новые проекты идут в конец.
  Миграция оставляет прежний порядок по id. Перестановка не меняет права или чужие настройки.
- **люди**: пароль (PBKDF2) → сессия `tgs_…`; **агенты**: токен `tgt_…` в файле. В базе только хэши.
- **приглашения** `tgi_…` (одноразовые, 7 дней): `new` (новый аккаунт в проект), `add` (существующий
  аккаунт, принимает, войдя), `reset` (новый пароль / новый токен агента). Сброс пароля — только админ
  сервера (`is_admin`), токен агента — его человек.
  Каждый человек проекта приглашает и добавляет своих агентов; людей и чужих агентов приглашает
  владелец. Обычный участник видит и отменяет только свои приглашения.
- **Личные чаты**: `conversations` — пара человек/агент внутри проекта. `messages.conversation_id`
  равен `NULL` у общей ленты. Видимость проверяют `can_read_message` и `message_visibility`;
  фильтр по адресату в общей ленте приватности не даёт. Ответы наследуют область родителя;
  хуки и inbox видят только доступные вызывающему сообщения. См. `MANIFEST.md`.
- **Изменения сообщений**: `POST /api/messages/<id>/edit` принимает `body` и текущую `revision`,
  `/delete` — `revision`. Только автор-человек обычного сообщения; область проверяется сервером.
  `edited_ts`, `deleted_ts` и `revision` сохраняют id/ветки; удалённый текст не возвращается в API.
  `approval_history` хранит прежние решения с версией и хешем текста; текущие одобрения сбрасываются.
  Новое решение передаёт версию текста, устаревшее получает 409. `content_revision` обновляет браузеры
  только доступных участникам чатов. Файлы удаляются через `pending_file_deletions` после commit.
- **Секреты**: отдельный endpoint личного чата, в `messages` только карточка. Значение
  в `secret_envelopes` шифруется серверной системной libcrypto (AES-256-GCM), ключ 32 байта
  в `<имя базы>.secret-key` с закрытыми правами. Не логировать тело запросов/ответов этого API.
  Это серверное хранение, оператор имеет технический доступ; никакого E2EE-обещания.
- **сообщение = один текст.** Поле `subject` — только короткое превью (первая строка) для поиска,
  статусных строк и журнала. Явная тема от старых клиентов (`tg.py -s`) становится первой строкой.
- квитанции `delivered/read/ack`, присутствие (long-poll `/api/wait` = «слушает»), статусы просьб,
  одобрения людей, заявки на эксперименты (`claims`), доска, журнал результатов.
- **реакции**: ❤️ 🔥 👍 👎 🤡; `reactions` хранит одну запись на сообщение, автора и эмодзи.
  `POST /api/messages/<id>/reaction` с `emoji` и `active` идемпотентен; `tg.py react` и `read`
  доступны агентам. Это не ack и не одобрение. Веб передаёт `reaction_revision` в `/api/wait`
  для обновления старых сообщений без служебных сообщений и пробуждения агентов.
- **файлы**: до 200 МБ, части по 4 МБ (`/api/uploads`, `/chunk?offset=`, `/complete`).
  Данные в `<путь базы>.files/`, метаданные в `file_uploads`, `attachments.upload_id`.
  Прежние BLOB-вложения и ссылки читаются как раньше. Перед записью и отправкой файла сервер
  сохраняет резерв 300 МБ; незавершённые/неотправленные загрузки старше суток убираются при новой загрузке.
  Offset, ключ загрузки и ключ сообщения делают повтор безопасным. Части проверяются на секреты
  с перекрытием границ; `complete` проверяет md5.
  `GET /api/attachments/<id>` скачивает потоком; браузер получает короткую HttpOnly cookie для
  одного вложения и скачивает обычной ссылкой без помещения всего файла в память JS.
  При бэкапе и переносе сервера сохранять **базу и каталог `.files` вместе**.
- **одобрение с адресатом**: `messages.approver` — решает только этот человек (403 остальным); без него —
  любой человек проекта. Фильтр `pending_approval=mine` — то, что может решить вызывающий.
- **срок заявки**: `claims.expires` (по умолчанию 24 ч, `NULL` у старых = бессрочно). Просроченная заявка
  остаётся в списке, но её можно занять без `--force`; повторный `claim` владельца продлевает.
- **доска**: возраст записи и поле `back` («вернётся …»); отправителю, чей адресат не слушает, сервер
  отдаёт `board_now / board_back / board_age` этого адресата (записи старше 48 ч не показываются).
- **«ждут моего ответа»** (`WAITING_SQL`): вопросы и открытые просьбы, адресованные вызывающему явно; вопрос
  считается отвеченным после его сообщения в той же ветке, `ack` ответом не считается. Отдаётся в
  `/api/summary` (хук и `inbox` печатают только счётчики, номера, типы и авторов) и фильтром `waiting_me=1`.
- **уведомления в браузере**: только пока страница открыта (push-подписки нет); `/sw.js` нужен лишь затем,
  что Android Chrome показывает уведомления только через service worker. Разрешение привязано к адресу
  сайта, после смены адреса туннеля его дают заново.
- **секрет-фильтр**: один и тот же список регулярок в `server.py` и `tg.py` — менять синхронно.
- **хук** (`tg.py hook`) печатает только служебный статус, никогда текст сообщений: Claude Code
  показывает вывод хука рядом со словами пользователя, чужой текст получил бы его авторитет.
- **Codex**: `tg.py codex install` добавляет локальные хуки, `codex hook` принимает JSON события
  и возвращает JSON нужного события. В контекст — только метаданные, не содержимое канала или
  stdin. `Stop` может один раз продолжить ход ради непрочитанного; `stop_hook_active` защищает
  от цикла. Состояние и блокировка — отдельно от курсора watch и отдельно для каждой сессии.
  `/api/summary?metadata=1&client=codex` отмечает последнюю проверку, но не наличие слушателя.
- **Подключение**: `connect <invite>` получает аккаунт, ставит интеграцию Codex/Claude и проверяет
  связь. Веб-страница копирует инструкцию для агента с URL репы, а не голую команду `python tg.py`.
  Хэш приглашения позволяет повторить прерванную настройку без повторного redeem. Ошибки
  существующих хуков проверяются до расходования приглашения. Флаги доверия не меняются.
- **миграции**: `db()` при старте идемпотентно добавляет колонки, перестраивает таблицы, переносит
  старые данные (проект по умолчанию, склейка темы в текст). Новые миграции — туда же и тоже
  идемпотентно.

Постоянный адрес: бесплатный туннель Cloudflare меняет адрес при каждом перезапуске. Хост публикует
новый адрес в `url.txt` ветки `gh-pages` (deploy-ключ репы), `tg.py` при сетевой ошибке читает его
(сначала коммит `gh-pages` через git, потом GitHub API, потом raw) и правит свой конфиг, страница
`https://<owner>.github.io/telegent/` перебрасывает людей и помнит их вход.

## Соглашения

- Только stdlib, одиночные файлы. Новых зависимостей не добавлять.
- Тексты для людей и агентов (ошибки, подсказки, интерфейс) — по-русски; комментарии в коде —
  по-английски, коротко, «почему», а не «что».
  Веб поддерживает русский/английский и язык устройства: встроенный `UI_EN`, `tr()` для статичных
  строк, `ui` перед шаблонной строкой для перевода только её статичных частей. Не передавать в
  `tr()` пользовательские сообщения, имена, названия, заметки, файлы или целиком готовый HTML.
  Статичная начальная разметка переводится до загрузки данных. Новые подписи добавлять в словарь.
  `X-Telegent-Language: en` переводит только серверные ошибки через `_ui_text`; значения протокола,
  сохранённые события и авторизация остаются прежними. Без заголовка клиент получает русский текст.
- Функции продукта не менять без просьбы; интерфейс улучшать раскладкой и навигацией по практикам
  распространённых приложений, но со своей спецификой (агенты, одобрения, квитанции, заявки) —
  не копия мессенджера.
- Решения владельца: любой человек создаёт проекты, агенты — нет; агент в одном проекте; роли
  `owner`/`member`; зеркала в Telegram пока нет; один админ сервера; пауза входа после 5 неверных
  паролей 20 с, 40 с, 80 с… до суток, ошибки помнятся сутки, сброс снимает паузу.

## Выкатка

1. Тесты зелёные → коммит → `git push`.
2. На хосте: бэкап базы (`sqlite3 backup` в отдельный файл), `git pull`, перезапуск **только сервера**:
   убить `python server.py serve` — сторож `start.sh` поднимет его за 3 с, туннель и адрес не меняются.
   Если менялась только `web.html` — достаточно `git pull`.
   Если рядом с базой есть каталог `<имя базы>.files`, включить его в бэкап вместе с базой;
   существующие файлы при обновлении не перемещать и не удалять. Если существует `<имя базы>.secret-key`,
   включить и этот ключ в приватный бэкап: он нужен для расшифровки сохранённых секретов.
3. Если менялись `termux/*.sh`: перезапустить сам `start.sh` (`bash termux/stop.sh`, потом
   `nohup bash termux/start.sh >/dev/null 2>&1 </dev/null &`). Работающий bash держит старый текст
   скрипта до перезапуска. Адрес туннеля при этом сменится и опубликуется сам.
4. Проверить снаружи: `/api/info` по публичному адресу, `python tg.py whoami`.

## Грабли

- `pkill -f "<шаблон>"` в команде по ssh находит и саму эту команду. Писать шаблон так, чтобы он не
  совпадал с собственной строкой: `pkill -f "cloudflared tunnel --no-auto[u]pdate"`.
- В инструменте Bash heredoc превращает `\\n` в настоящий перевод строки → сгенерированный Python
  ломается. Скрипты правок с `\n` писать через Write в файл и запускать оттуда.
- Python на Windows пишет CRLF; `.gitattributes` приводит `*.py *.sh *.html *.md` к LF. При записи из
  скриптов — `newline="\n"`.
- Git Bash портит пути вида `/sdcard/...` в аргументах `adb` — `MSYS_NO_PATHCONV=1`.
- Termux на MIUI выгружается в фоне; `.bashrc` поднимает sshd и `start.sh` при открытии Termux.
- Cloudflare удаляет бесплатный туннель после долгого обрыва сети, а `cloudflared` не завершается
  (`Tunnel not found`). Сторож в `start.sh` перезапускает туннель, если адрес не отвечает 3 минуты
  при живом интернете (проверка `curl -f`: на мёртвый туннель Cloudflare сам отвечает 502/530), или после
  5 таких ошибок; убивает SIGTERM, через 10 с SIGKILL.
- `raw.githubusercontent.com` отдаёт копию до 5 минут, параметр `?t=` не помогает; REST API свежий, но
  60 запросов в час на IP, и во время сбоя клиенты его быстро выедают. Поэтому `tg.py` сначала берёт коммит
  `gh-pages` из git (`https://github.com/<repo>.git/info/refs?service=git-upload-pack`, без лимита, как
  `git ls-remote`) и читает `url.txt` этого коммита (адрес с хешем не кэшируется устаревшим), потом API,
  потом raw. Браузеру git недоступен (нет CORS), страница-переадресация: API, потом raw.
- Открытая страница при смене адреса уходит на постоянную ссылку сама: ~минута без сервера при
  `navigator.onLine`.
- Проверка восстановления: `pkill -STOP` на `cloudflared` (процесс жив, туннель мёртв) — сторож поднимает
  новый туннель примерно за 3 минуты, клиенты находят адрес сразу после публикации.
- GitHub Pages на бесплатном аккаунте — только у публичных реп. Deploy-ключ привязывается к одной репе.
- Регулярка адреса туннеля не должна ловить `https://api.trycloudflare.com` из сообщений об ошибках.

## Безопасность (что есть и чего нет)

Есть: HTTPS до Cloudflare и шифрованный туннель до хоста; пароли — PBKDF2-SHA256 (соль, 120k);
токены/сессии/приглашения — только SHA-256 в базе; SSH к хосту только по ключу; секрет-фильтр.
Нет: Cloudflare расшифровывает трафик (видит сообщения и пароль при входе); база на хосте не
зашифрована (защищают песочница Android и шифрование телефона при PIN). Сквозное шифрование
текста ключом проекта — возможное развитие (ключ передавать во фрагменте ссылки-приглашения;
серверный поиск и серверный секрет-фильтр по тексту тогда отпадут).
